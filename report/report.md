## Лабораторная работа №2

### Тема
Создание процессов и взаимодействие между ними через каналы

### Цель работы

Получить практические навыки управления процессами в ОС и обеспечения обмена данных между процессами посредством каналов. Среда сборки и запуска - Ubuntu в WSL.

### Постановка задачи

Составить и отладить программу на языке Си, осуществляющую работу с процессами и взаимодействие между ними в одной из двух операционных систем. В результате работы программа (основной процесс) должен создать для решение задачи один или несколько дочерних процессов. Взаимодействие между процессами осуществляется через системные сигналы/события и/или каналы (pipe). Необходимо обрабатывать системные ошибки, которые могут возникнуть в результате работы.

Задание моего варианта:

Родительский процесс создает дочерний процесс. Первой строчкой пользователь в консоль родительского процесса вводит имя файла, которое будет использовано для открытия файла с таким именем на чтение. Стандартный поток ввода дочернего процесса переопределяется открытым файлом. Дочерний процесс читает команды из стандартного потока ввода. Стандартный поток вывода дочернего процесса перенаправляется в pipe1. Родительский процесс
читает из pipe1 и прочитанное выводит в свой стандартный поток вывода. Родительский и дочерний процесс должны быть представлены разными программами.

В файле записаны команды вида: «число\<endline>». Дочерний процесс производит проверку этого числа на простоту. Если число составное, то дочерний процесс пишет это число в стандартный поток вывода. Если число отрицательное или простое, то тогда дочерний и родительский процессы завершаются. Количество чисел может быть произвольным.

### Алгоритм решения

1. Родитель читает с консоли имя файла через fgets в буфер фиксированного размера, удаляет завершающий символ \n и отклоняет пустую строку. Перед созданием дочернего процесса родитель проверяет возможность открытия файла на чтение через open с флагом O_RDONLY и сразу закрывает проверочный дескриптор.

2. Родитель создаёт один канал pipe1 через pipe и один дочерний процесс через fork. В родителе write-конец канала (pipe1[1]) сразу закрывается, чтобы read мог получить EOF после завершения ребёнка. Диагностические сообщения с PID направляются в stdout и stderr.

3. В ребёнке перед execl через dup2 перенаправляется стандартный ввод на унаследованный дескриптор файла, а стандартный вывод на write-конец канала pipe1[1]. После перенаправления закрываются исходные дескрипторы файла и оба конца канала. Затем через execl запускается отдельная программа child без аргументов.

3. Ребёнок построчно читает числа из своего стандартного ввода через scanf в цикле. Для каждого числа выполняется проверка на простоту функцией is_prime, реализованной перебором нечётных делителей до √n.

4. Если число отрицательное, ребёнок завершается с кодом 0. Если число простое, ребёнок также завершается. Иначе (число составное) ребёнок выводит его в стандартный поток вывода через printf и форсирует запись через fflush(stdout), чтобы данные немедленно ушли родителю через канал.

5. Родитель читает из read-конца канала pipe1[0] в цикле read и выводит прочитанное в свой стандартный поток вывода через write. Чтение продолжается до EOF (когда все write-концы канала закрыты, то есть ребёнок завершился). После цикла родитель закрывает pipe1[0] и получает статус ребёнка через waitpid, разбирая его макросами WIFEXITED и WEXITSTATUS.

6. Используются две исполняемые программы — parent и child; их исходные файлы — parent.c и child.c. Во время работы существуют два процесса: один родительский и один дочерний. Родитель создаёт ребёнка через fork, затем в дочернем процессе через execl запускается отдельная программа child.

7. Файл открывает дочерний процесс самостоятельно после fork - программа parent только проверяет доступность файла и передаёт его имя ребёнку через унаследованную копию адресного пространства (через execl). Ребёнок получает stdin, перенаправленный на файл, и stdout, перенаправленный в канал. Общих модулей нет, вся логика ребёнка содержится в child.c, вся логика родителя - в parent.c.

### Ввод и вывод программы
Ввод: одна строка с именем файла, затем содержимое этого файла — числа вида число\<endline>. Количество чисел не ограничено. Проверка на простоту выполняется для каждого числа.

Вывод: составные числа из файла выводятся в стандартный поток вывода родителя. Отрицательные и простые числа не выводятся, а служат сигналом завершения обоих процессов. Диагностика показывает PID дочернего процесса и статус его завершения.
